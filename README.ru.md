## Какую задачу это решает

Приборная панель DiLink 5 — это **проекционный экран, входящий в состав самого головного
устройства**; создавать его не нужно, да и не следует:

| displayId | Имя | Размер | Ключевые свойства |
| --- | --- | --- | --- |
| 0 | Встроенный экран | 1920×1080 | layerStack 0, единственный экран HWC |
| 2 | `fission_bg_XDJAScreenProjection` | 1920×720 @320 | layerStack 2, `touch NONE`, владелец `com.byd.containerservice`(uid 1000) — **это и есть приборная панель** |
| 3 / 4 | `shared_fission_bg_XDJAScreenProjection_0/1` | 1920×720 | layerStack 3/4 — **слоты трансляции**, `screencap` даёт полностью чёрный кадр |

Когда обычное приложение пытается отправить другое приложение на дополнительный дисплей, AMS сразу
отклоняет это:

```
SecurityException: Permission Denial: ... with launchDisplayId=2
```

**Но `uid 2000` может.** Поэтому всё сводится к одной настоящей проблеме:
**сделать так, чтобы приложение само получило uid 2000.**

## Основные механизмы

1. **Самостоятельное подключение к локальному ADB** — приложение подключается к loopback-интерфейсу
   устройства `127.0.0.1:5555` с помощью ключа, сгенерированного при первом запуске (или встроенного
   при сборке), проходит рукопожатие по стандартному проводному протоколу ADB и получает канал
   `shell,v2,raw:`. На всём пути компьютер не нужен.
2. **Запуск привилегированного процесса с uid 2000** — привилегированный код **лежит в dex того же
   самого APK** и запускается через `app_process` с `CLASSPATH=<установленный APK>` и
   `--nice-name=com.byd.dashcast-priv`. Отдельный jar-агент не нужен, и никакие файлы на устройство
   не записываются.
3. **Трансляция** — отправка целевого приложения на **display 3 (слот трансляции)**: если задачи нет —
   `am start-activity --display 3`, если задача уже есть — `am display move-stack <taskId> 3`.
   Сопоставление слота с приборной панелью выполняет собственный `com.byd.containerservice` головного
   устройства; этот проект в это не вмешивается.
4. **Предпросмотр** — в главном интерфейсе есть `TextureView` в масштабе 1:1 с приборной панелью.
   Привилегированный процесс через `SurfaceControl` переиспользует layerStack приборной панели и
   **подключает результат её композиции прямо к этой Surface**: без захвата кадров, без кодирования и
   декодирования, без чтения из CPU.
5. **Инъекция касаний** — поверх предпросмотра лежит прозрачный слой с той же системой координат;
   события пальца привилегированный процесс инжектирует на приборную панель через
   `InputManager.injectInputEvent`. **У дисплея приборной панели `touch NONE`, поэтому любой ввод
   необходимо инжектировать.**
6. **Удержание позиции** — когда приложение само запускает Activity без указания display, AMS
   возвращает всю root task на дисплей по умолчанию; это поведение на стороне приложения,
   предотвратить его нельзя, можно лишь вернуть всё обратно постфактум. Возвратом занимается
   foreground-сервис `CastGuardService`: после установления трансляции он раз в 2 секунды выполняет
   периодическую проверку, **и продолжает её даже после выхода из интерфейса**; чтобы забрать
   трансляцию, пользователь нажимает в постоянном уведомлении кнопку 「收回投屏」 («остановить
   трансляцию»), и после возврата цели на главный экран сервис останавливается. Он не истекает сам и
   не приковывает пользователя к дополнительному дисплею.

Программная структура — в [`docs/SOFTWARE_STRUCTURE_ZH.md`](docs/SOFTWARE_STRUCTURE_ZH.md) (только на китайском).

## Сборка

Требования: JDK (`JAVA_HOME`), Android SDK с `build-tools;35.0.0` и `platforms;android-32`.
Путь к SDK читается по порядку: `ANDROID_HOME` → `ANDROID_SDK_ROOT` → `%LOCALAPPDATA%\Android\Sdk`;
`preflight` печатает результат разрешения пути и при отсутствии зависимости сразу завершается с ошибкой.

```powershell
.\apk\build.ps1 -NoInstall
```

Результат — `apk\dashcast.apk`. Цепочка такая:
`preflight → assets → aapt2 compile → aapt2 link → javac → d8 → aapt add → zipalign → apksigner`.

- Уберите `-NoInstall` и добавьте `-Serial <ip:port>`, чтобы установить сразу на головное устройство.
- `apk\build.ps1 -BundledKey <путь-к-ключу.pk8>` позволяет встроить в APK фиксированный приватный ключ ADB.
  **Можно и не встраивать**: при первом запуске приложение само сгенерирует пару ключей и сохранит её
  в собственном каталоге; цена — один запрос авторизации ADB на головном устройстве, который нужно
  подтвердить.
- Если `apk\debug.keystore` отсутствует, сборочный скрипт сам выполнит `keytool -genkeypair`;
  свой файл готовить не нужно.

**Для обновления уже установленной на головном устройстве сборки необходимо использовать тот же ключ
подписи**:

```powershell
.\apk\build.ps1 -Keystore <путь к keystore> -StorePass <пароль хранилища> -KeyAlias <псевдоним>
```

Без `-Keystore` скрипт по-прежнему откатывается на `apk\debug.keystore`; `debug.keystore` подходит
только для чистой установки и никогда не сможет обновить сборку на головном устройстве, подписанную
другим ключом. Если передать `-Keystore`, а файла нет, скрипт **сразу завершится с ошибкой** и не
откатится на временный ключ — иначе получился бы APK, который невозможно установить.

## Требования

- На головном устройстве включена **беспроводная отладка ADB**. В DiLink 5 эта цепочка такая:
  `sys.connect.adb.wiress=1` → init `setprop service.adb.tcp.port 5555` → перезапуск adbd.
- Приложение подключается к **loopback-интерфейсу головного устройства** `127.0.0.1:5555`,
  на всём пути компьютер не нужен.

## Первый запуск

Точка входа на рабочем столе — это **главный интерфейс** (`CastActivity`). Если авторизации ещё нет,
он переходит на экран-подсказку авторизации, и головное устройство показывает 「允许 USB 调试吗」
(«Разрешить отладку по USB?»). Здесь есть одно действие, которое необходимо выполнить правильно:

- В диалоге **нужно установить галочку 「一律允许使用这台计算机进行调试」 («Всегда разрешать отладку
  с этого компьютера») и только затем нажать 「允许」 («Разрешить»)**: нажатие только 「允许」 не
  запишет открытый ключ в `adb_keys`, и при следующем открытии диалог появится снова.
- У авторизации 「一律允许」 («always allow») есть **период ожидания** (значение по умолчанию во фреймворке
  604800000 ms = 7 days): если в течение этого срока ни одного успешного подключения не произошло,
  фреймворк удалит ключ из `adb_keys` и покажет диалог заново. **Текущий исходный код ничего с этим
  не делает** (он ни записывает `adb_allowed_connection_time`, ни выполняет каких-либо других действий
  по продлению), поэтому после долгого простоя автомобиля авторизацию, возможно, придётся пройти ещё
  раз. Это известное ограничение, см. раздел 12.2 в
  [`docs/SOFTWARE_STRUCTURE_ZH.md`](docs/SOFTWARE_STRUCTURE_ZH.md) (только на китайском).
- После авторизации подключение происходит автоматически при каждом включении, больше никаких
  действий не требуется — **при условии, что цепочка «автозапуск при загрузке» действительно работает,
  а она пока не проверена в чистых условиях** (см. также раздел 12.1).

## Интерфейс

- Вся разметка выполняется в `px` (головное устройство 1920×1080 @240dpi, 1dp = 1.5px), потому что
  физический размер этого экрана фиксирован.
- Тема — `Theme.DeviceDefault.NoActionBar` плюс полупрозрачное окно — полупрозрачность
  **структурно необходима**: «полупрозрачно ли окно» определяется темой манифеста в момент создания
  окна, и `setTheme()` внутри `onCreate` этого изменить не может.
- Корневая разметка самого интерфейса — непрозрачный тёмный фон; только путь автозапуска при
  загрузке, который не вызывает `setContentView`, оставляет всё окно полностью прозрачным, и
  пользователь его не видит.
- Спецификация интерфейса — это отдельный HTML-макет предпросмотра (рендерится 1:1 в 1920×1080),
  **его нет в этом репозитории**.

## Известные ограничения

- **Запись файла идентичности ADB не является устойчивой**. `AdbKeyStore.write()` перезаписывает файл
  напрямую: без `fsync`, без временного файла и атомарной замены, без проверки чтением. После
  пропадания питания на головном устройстве файл может вернуться в виде «длина правильная, содержимое
  полностью нули», быть признан повреждённым, удалён и создан заново, и пользователь снова увидит
  диалог авторизации. Это известная первопричина, пока не исправлена.
- **Верхний предел частоты кадров предпросмотра определяет само транслируемое приложение**. При
  измерении во время перетаскивания карты навигации этот экран сам выдавал всего около 7.3 fps;
  предпросмотр — точное зеркало, сам путь никакого предела не задаёт. При выключенном предпросмотре
  и том же перетаскивании кадров оказалось даже чуть меньше, что позволяет исключить «новый display
  отбирает GPU».
- **При статичном содержимом изображение прямого прохода «замерзает» на последнем кадре** — это не
  неисправность: SurfaceFlinger не выполняет повторную композицию неизменившегося стека слоёв.
  Поэтому по признаку «картинка не меняется» нельзя судить, жив ли другой конец.
- **Задержка касаний от начала до конца пока не измерена**. Достоверно известно, что каждое событие
  превратилось из «fork отдельного процесса (40~140 ms на одно событие)» в «один односторонний вызов
  Binder».
- **Задержка восстановления при удержании позиции измерена**: после принудительного возврата целевой
  задачи на главный экран (`am display move-stack <id> 0`) следующая периодическая проверка (≤2 s)
  возвращает её в слот трансляции, и в `dashcast.log` остаётся след. Интервал проверки — 2 s, поэтому
  худшая задержка равна 2 s.
- **Автозапуск при загрузке (`BootReceiver`) на этом автомобиле не выполняется**: изменённая очередь
  широковещательных сообщений головного устройства пропускает широковещательные сообщения о загрузке
  от сторонних приложений (`BroadcastQueue: skip reciever for uid … BOOT_COMPLETED … ignored !!!`,
  дословно с устройства). Поэтому канал ADB приходится открывать после того, как приложение будет
  запущено, а «установил и забыл» верно только для **приложений, которые головное устройство
  запускает само** — см. раздел 「已知边界与未确认项」 («Известные ограничения и неподтверждённые
  пункты») в [`docs/SOFTWARE_STRUCTURE_ZH.md`](docs/SOFTWARE_STRUCTURE_ZH.md) (только на китайском).
- Остальные ограничения перечислены в разделе 「已知边界与未确认项」 («Известные ограничения и
  неподтверждённые пункты») в [`docs/SOFTWARE_STRUCTURE_ZH.md`](docs/SOFTWARE_STRUCTURE_ZH.md)
  (только на китайском).
